作成: 2026-11-18（JST）／ 対象: `realoria_cc` v0.1.0-poc（ブランチ `claude/realoria-ai-agent-system-j5arvu`）

## 0. 結論（要旨）

1. **提供資料の不足により、REALORIA固有の権限や承認の設計は確定できません。** 正式情報源、UI試作v0.4、参考画像、Codexのコードと監査結果は未提供です。このため、33機能は番号と所属本部だけを確定値とし、承認処理は無効化した状態で実装しました。
2. **基盤部分**（ジョブ制御、リース・フェンシング、緊急停止、Hold隔離、権限分離、データ区分、外部送信の遮断、監査保全、根拠検査、UI）を、模擬AIで端から端まで動く状態にしました。自動テストは72件で、すべて成功しています（Linux / Python 3.13）。
3. **運用実証は済んでいません。** 実LLMへの接続、Windows実機での動作、24時間連続稼働、実際の取材データでの検証は、いずれも行っていません。
4. Codex版との比較は、**観点と比較方法を整理した段階**です。Codexのコードを受領していないため、優劣は判断していません。

## 4. テスト結果

実行コマンド: `python -m unittest discover -s tests -t .`
結果: **72件実行、72件成功**（2026-11-18、Linux、Python 3.13.18、SQLite 3.53.1）

| ファイル | 件数 | 主な検証内容 |
|---|---|---|
| test_org_and_security.py | 24 | 33機能の整合性、Signal限定、未照合時の承認無効、認証・ロック・期限、役割分離、AIの権限制限、区分による遮断 |
| test_jobs.py | 17 | 冪等性、同時claim、旧所有者の書込み拒否、期限切れ、再試行上限、Hold隔離、一時停止・中止、モデル変更の拒否、緊急停止、再起動後の復旧 |
| test_audit_backup.py | 13 | トリガー、改変・削除・切り詰め・鍵なし再計算・アンカー改変の検知、異常時の自動停止、バックアップと復元 |
| test_agents_api.py | 18 | 根拠検査、捏造検知、外部送信の遮断、上限、送信内容をハッシュのみで記録、HTTP（未認証の拒否、パストラバーサル、ヘッダ、緊急停止、承認403） |

テスト外で確認したこと: Playwright（Chromium）でPC幅 1360px と iPhone 13 相当で全画面を操作しました。コンソールエラーとCSP違反はなく、横スクロールも出ません。この確認で見つかった2件の不具合（チャット中の自動再描画で資料の選択が失われる、表示の崩れ）は修正済みです。

**未検証**: Windows実機、24時間以上の連続稼働、負荷（同時利用者数・ジョブ数）、実LLMの出力品質、スクリーンリーダー、Safari/Firefox。

## 5. セキュリティ評価（自己評価。第三者による監査ではありません）

| 脅威 | 対策 | 残存リスク |
|---|---|---|
| 未認証の操作 | 全APIで認証が必須（health のみ例外で最小限の情報） | — |
| 権限の昇格（AI → 人間権限） | ロール付与時の検査と、HUMAN_ONLY による実行時の拒否の二重化 | DBファイルへの直接書込みでセッションを偽造される可能性（OS権限で保護する必要あり） |
| 取材素材の外部流出 | 区分3は外部送信を常に拒否、外部送信は既定で無効、マイクも既定で遮断 | 利用者が区分を誤って低く申告した場合（資料側の区分で引き上げられるが、資料を登録せずに本文を直接貼り付けた場合は防げない） |
| 監査の改ざん | 3層の保全、異常時の自動停止 | 同一OSの管理者権限があれば鍵とアンカーも改ざんできる |
| XSS | `textContent` による描画、CSP `script-src 'self'`、インラインスクリプトなし | — |
| CSRF | Bearerトークン（Cookieなし）、`application/json` のみ受付 | — |
| パストラバーサル | 解決後のパスがUIディレクトリ配下かを検査 | — |
| 総当たり | 5回失敗で15分ロック | ロックを悪用した妨害（特定IDを意図的にロックさせる）。存在しないIDではscryptを計算しないため、応答時間の差でIDの有無が推測される可能性 |
| プロンプトインジェクション | 資料の区切り、データとして扱う旨の指示、出力は下書きのみで実行権限なし | LLM自体を騙す攻撃は防げない。被害を下書きの範囲に限定しているのみ |
| 暴走・費用 | 日次の呼出・費用上限、単価未設定時の拒否 | 1回あたりの長大な出力は制限していない |
| トークン漏えい | sessionStorage に保存（タブを閉じると消える）、DBにはハッシュで保存 | 端末側のマルウェアには対抗できない |

## 7. 残存リスク

| リスク | 影響 | 対応方針 |
|---|---|---|
| 正式権限が未照合のまま運用されること | 誤った承認経路が生まれる | 承認は無効化済み。照合完了を有効化の条件にする |
| SQLite と単一プロセス構成 | 単一障害点、同時書込みの上限 | 当面は単一PC運用に限定。拡張が必要になれば PostgreSQL へ |
| 鍵とアンカーが同一ディスク上にある | 管理者権限を持つ者による改ざん | DPAPI と別媒体化（次工程） |
| Windows 未検証 | 導入時の不具合 | 次工程の最初に実機検証 |
| 実LLMでの挙動が未知 | 根拠検査をすり抜ける誤り | 引用の忠実性検査と、人間によるレビューを必須にする |
| 運営負荷 | Hold・要確認の滞留 | ホーム画面に件数を表示済み。滞留時間の可視化は次工程 |
